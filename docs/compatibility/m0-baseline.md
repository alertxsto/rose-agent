# Compatibility status and historical baseline

This page records observed behavior, not universal compatibility. Current usage/build instructions are in the [desktop and CLI guide](../usage/native-cli.md); future acceptance gates are in the [public roadmap](../../ROADMAP.md).

## Evidence levels

- **Verified:** a specific operation was actually exercised and checked; evidence scope is stated.
- **Unverified:** there is no relevant runtime proof. A successful build or adjacent test is not substituted for the missing operation.
- **Unsupported:** the current product intentionally does not offer that operation/profile. Preserving foreign source is not authoring support.

## Native supplier-order repair and missing proof

A populated imported native model referenced view suppliers before their declarations. A guarded sibling repair reordered only five raw object spans into numeric/dependency order, preserving three classes, 16 members, two relationships, five appearances, all identities and explicit geometry/routes. Independent CLI reopen and actual Linux canvas rendering passed. An explicit off-box endpoint remained unchanged; source preservation is not automatic geometry correction.

Fresh native verification of that repair and newer live-AI outputs remains missing. A permitted read-only screenshot attempt failed; the display reported 0 bits per pixel. No Windows input, guest command, install/configuration/license change or simulated native result replaced that missing observation. The older exact Petal 44 acceptance remains valid but cannot certify newer exports by association.

## Windows platform basis

Qt's [official Qt 5.15 Windows table](https://doc.qt.io/archives/qt-5.15/windows.html) lists Windows 8.1 x86 with MSVC 2019. The dedicated legacy release configuration uses official Qt 5.15.18 source and Schannel rather than obsolete OpenSSL 1.1 deployment. Upstream support, successful compilation, complete deployment and actual app execution are distinct gates.

[Windows 8.1 reached end of support January 10, 2023](https://learn.microsoft.com/en-us/lifecycle/products/windows-81). A legacy executable cannot restore OS support/security updates or guarantee compatibility with evolving provider TLS policies. Actual guest acceptance needs model create/import/manual edit, real AI discovery/photo/history, exact review/apply/reject, separate save/reopen and Windows Credential Manager behavior. No such complete guest proof is currently claimed.

## Historical baseline — October 2, 2026

The initial snapshot built only a parser target, not the complete application. Parser source preservation, explicit codec/error cases and isolated canvas/JSON behavior were exercised. The root CLI target was absent; semantic Model/ControlledUnits implementations and desktop/provider integration blocked complete open → inspect → proposal → apply → undo/redo → save → independent reopen. No real provider or native Rose runtime was exercised in that baseline.

Those historical implementation blockers were subsequently resolved by the shared workspace, controlled-unit, CLI, desktop and agent integration described above. They are **not current product failures**. The baseline remains useful only for distinguishing syntax/isolated-widget proof from later complete runtime evidence; local toolchain paths and temporary probe commands are not public installation instructions.

See [corpus provenance](corpus-provenance.md) for research rights and syntax-only evidence, and [Petal profile documentation](../format/petal-50.md) for parser versus editable-model boundaries.
